## 审查范围与已修复问题

核对 v1.4.0 至 1.4.1 的代码变更、四类网络客户端与缓存仓库、榜单协议和基准隔离、模型动态目录、刷新任务、费用实验功能开关、账户隔离与更新/打包路径，并运行全套既有回归。账户、用量、更新功能没有新增行为；本轮不修改客户端 UI。

1. 推荐、官方费率和 API 价格的 HTTP 200 响应未提供 ETag/Last-Modified 时，原代码会沿用上一份内容的验证器。现仅在 304 时保留旧验证器，200 会清除缺失值，避免后续错误沿用旧缓存标识。
2. 推荐数据显式回退为 historical 后，原代码只检查 upstream_error，会把回退结果当成正常新数据。现 historical 在读取缓存、网络更新和 304 后均保持历史状态。
3. 推荐仓库原只检查 revision 倒退；现同时拒绝 generation 倒退、已托管内容退回无元数据响应，以及相同 revision 被改写内容。合法更高 generation 的回退仍可生效。
4. 本地 JSON 缓存中重复模型、重复费用点可能触发 Dictionary(uniqueKeysWithValues:) 的进程终止。现加载时拒绝重复模型，费用点按最新记录合并，并过滤无效旧费用。

上述问题已有针对性回归测试。没有发现需要继续阻止生成候选包的已知客户端问题；自动测试不能证明所有系统和真实账户场景绝对无缺陷。

## 公共数据后续维护

四类公共数据端点均固定在 zjwspace.cn/api/codex-toolbox/v1/。后台支持直接读取/编辑当前数据、校验预览、通行密钥确认启用、回退。手工启用与暂停自动同步在同一状态事务完成；榜单保留兼容历史，价格与费率只追加新生效版本，旧历史不可覆盖。

同一个 CoreVerification 二进制（SHA-256 71a00e2232a0d6e03a1291574fc710a73d862d5448fef0ff3dccd9596beb41e0）通过同一组 URL 读取两种榜单适配器、推荐修改、费率回退以及四类手工发布结果。合成数据仅用于隔离临时 HTTP 服务，没有发布到生产。

现有协议中的模型、档位、指标、评分名称、来源和价格调整无需客户端发版。新的推荐场景、计费维度、评分方向、协议或原生功能仍需评估客户端更新。软件升级包与 Sparkle 更新源继续使用 GitHub，用户账户和本机用量保持原有读取方式，不上传网站。
