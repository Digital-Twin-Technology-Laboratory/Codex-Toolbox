# Codex Toolbox 1.4.0 / Build 57 任务名称修复与交付记录

日期：2026-10-05。基于用户测试后的 Build 56，仅修复任务名称读取并制作最终预发布安装包。

## 根因及证据

只读核对本机 `state_5.sqlite` 的任务字段：截图对应任务的 `name` 为“优化用量文案并制作预发布包”，而 `title` 以 `# Files mentioned by the user` 及附件路径开头。`title` 保存了初始消息内容，并非当前侧栏显示名称。

代码存在两套路径：`nativeCatalogue()` 已优先读取 `name`；用量榜单使用的 `inventory()` 仍只读 `title`，随后将它存入用量账本。标题解析器将附件说明判定为普通非空标题，所以原样显示。此前针对原生目录的名称测试没有覆盖真正供榜单使用的 `readUsage()` 路径。

## 修复

- `inventory()` 根据数据库实际列结构读取 `name`，优先使用非空显示名称；缺少该列、NULL、空串或纯空白时保留已有旧版回退逻辑。
- 用户明确命名为“任务 1”等形式时也尊重该名称，不以通用标题规则覆盖。
- 原生目录复用相同解析结果，删除独立名称查询，避免两个模块再次不一致。
- 保留原有每次刷新更新账本标题的流程；即使 rollout 没有新增、已归档或文件不可用，现存数据库中的改名仍会更新，历史 Token 保留。
- 不更改任务 ID、父子关系、Token 计算、额度估算、数据库内容或账本格式；不需要清空历史。
- 版本仍为 1.4.0，Build 递增为 57。
