## 如何使用

按编号给出新文案即可，例如 `U01 → 新文案`。原文保留 Swift 的 `\(变量)` 占位表达式；花括号表示本表概括的运行时变量。R、F、P 的“具体原因”会嵌入外层错误模板，并不等于每个原因都有独立弹窗。标点和空格按源码保留。

统计按条目而非唯一中文句子：同文不同触发点可分行；固定模板和嵌入原因分开计数；动态系统错误按入口计数。N 是异常附近的空态／状态文案，不都属于报错。I 当前无普通 UI 展示入口。S 来自 Sparkle，已与当前构建所用框架资源逐条比对一致，不能当作项目自有文案直接修改。

这是源码、展示调用链与依赖资源的静态清单，不是所有故障均已在设备上复现。macOS、SQLite、JSON 解码器、浏览器和 Sparkle 可能产生随环境变化的补充错误；不能给它们虚构一个有限的“全部原文”列表。系统安装器／Gatekeeper 的全量文案不在项目控制范围内。

## 展示规则与值得注意的现状

- 榜单短暂断网且有缓存时不显示详细网络报错，仍有“刷新失败 · 本地缓存”状态；无缓存时显示网络重试提示。
- 推荐仓库的详细错误当前未被推荐卡读取，用户看到“暂无推荐”或“已过期”等状态。
- 本机用量有错误时优先显示错误，否则仅显示 warnings 的第一条；记录中仍可能保存更多警告。
- 重置卡有缓存时，超时和临时服务错误被隐藏，继续展示缓存；账户身份变化后会丢弃旧账户结果。
- 费用实验功能未启用时，相关请求和设置提示不出现；原生分析错误主要在任务额度悬浮说明中出现。
- 更新设置的错误会被归一化；Sparkle 自带窗口另有依赖文案。后台定时检查的网络失败在重试结束后可恢复先前状态。
- 初次榜单空态仍写“首次启动需要连接 CodexRadar 获取数据。”，与现在迁往自有接口的实现存在旧名称残留。
- 后台 422 使用共享内容编辑器文案“标题不能为空…”；Toolbox 配置操作通常返回 400，但此通用兜底仍存在。
- 后台未映射的任务异常只显示类型名，例如 `ValueError`；配置 JSON 语法错误和 fetch 错误还可能直接显示浏览器原文。
- 后台任务错误通常呈现为“未完成 · {原因}”；概览异常状态另有“历史数据”“同步异常”“暂无数据”，暂停状态为“已暂停”。维护接口返回的 `error` 字段不会直接显示，前端目前使用通用失败提示。
