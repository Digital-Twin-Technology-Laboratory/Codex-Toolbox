# 1.4.2 Build 64 真实设备验收

状态：**待用户安装验收**。下面的主线程、整应用 CPU、持续能耗、真实账户与安装结论不能由离线测试代替。本轮没有替换或启动临时候选应用。

## 对照条件

同一台 Mac，固定数据副本、账户、费率、时区、模型可见设置及刷新周期。先记录 Build 63，再安装 Build 64 重复操作。记录系统版本、电源模式、显示器、网络、Codex 活动和其他重负载；无法保持条件相同时不要把差异归为候选效果。

首次迁移单独记账。进入稳态后再开始 CPU、写盘及交互计时。记录应用及其 `toolbox-native-analytics`、账户读取子进程的总 CPU 时间和实际磁盘写入，不能只看单个瞬时百分比或主进程。

## 必测场景

| 场景 | 每轮要求 | 观察与记录 | 当前状态 |
|---|---|---|---|
| 面板收起 | 至少 30 分钟 | 多个一分钟/五分钟周期、CPU、写入、唤醒、内存、子进程数 | 待验收 |
| 面板展开静置 | 至少 30 分钟 | 同上，并确认数据刷新时效没有降低 | 待验收 |
| 连续交互 | 重复固定操作序列 | 柱状图选日、用量明细、连续上下滚动、收起再打开 | 待验收 |
| 电池/接电 | 分别重复后台场景 | 相同电源模式；系统能耗提示和实际计数同时记录 | 待验收 |
| 睡眠/唤醒 | 活跃请求期间反复执行 | 无旧结果覆盖、定时器恢复正常、无双轮请求或残留进程 | 待验收 |
| 持续观察 | 至少 2 小时 | CPU/内存趋势、历史增长、失联恢复、能耗提示 | 待验收 |

交互序列：连续选不同日期 → 返回今天 → 展开任务明细 → 连续上下滚动 → 快速改变选日 → 收起/再展开面板。使用 Instruments 的 Time Profiler/Hangs 记录相关主线程工作；每项不得出现超过 100 ms 的长任务，并单独确认原来可感知的卡顿已消失。

并发序列：A→B→A 账户切换；费率更新与用量刷新交错；请求中睡眠/唤醒；选日中切换设置；取消后立即返回。核对账户归属、Token、百分比、`=`/`≈`、缺失状态与更新时间。不得为了通过性能测试降低采样频率。

## 通过标准

- 整应用及辅助进程的受控稳态总 CPU 时间降低至少 50%，实际写入降低至少 90%。
- 固定新增量下，5 倍历史的写入不超过普通历史的 2 倍；启动迁移不计入稳态。
- 无跨账户污染、旧结果覆盖、重复整轮刷新、历史丢失、重复记录或已清除备份复活。
- 原卡顿消失且主线程长任务门槛通过；至少两小时观察没有持续增长的内存或残留进程。
