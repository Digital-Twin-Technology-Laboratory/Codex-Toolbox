# 每日 Token 下钻与额度权重修正设计

## 目标

点击“每日用量趋势”的任一柱形后，上方任务卡切换为该日期的根任务明细，并提供“返回今日”。关闭菜单栏弹窗时清除日期选择和任务展开状态，下一次打开始终从今日开始。

任务行的额度百分比必须与同一行的日期和任务一致。原实现把额度窗口内同一根任务的整周估算与“今日 Token”并列显示，因此一个任务今天只有约 250 万 Token、但本周此前已运行多次时，仍可能显示约 20% 的整周消耗。原实现还优先使用每个任务自己的 Token/百分点样本，一次受百分比取整、快照延迟或其他设备并发污染的样本会被继续放大。

## 交互

- 趋势图继续支持悬停查看精确值，并新增点击选择。
- 选中过去日期后，任务卡标题、总 Token、任务数量、进度条和“其余任务”都改用该日汇总。
- 过去日期显示独立的“返回今日”按钮；点击今日柱形等价于返回今日。
- 日期选择不写入设置或账本。收到弹窗关闭通知或视图消失时，日期和展开状态恢复默认。
- 柱形使用持久选中态和辅助功能提示，悬停态不覆盖选中态。

## 额度估算

OpenAI 当前公开口径说明，Codex 用量会受模型、上下文、推理、工具和缓存影响；信用消耗按输入、缓存输入和输出 Token 使用不同费率计算。因此原始 `total_tokens` 只能用于本机审计，不能作为所有任务等价的额度权重。

解析 rollout 时继续保存原始单轮 Token，同时根据事件前最近的 `turn_context.model` 和 `last_token_usage` 生成脱敏的额度权重：

`未缓存输入 × 输入权重 + 缓存输入 × 缓存权重 + 输出 × 输出权重`

权重依据 OpenAI Codex rate card（https://help.openai.com/en/articles/20001106-codex-rate-card）于 2026-08-02 再次核对，并按 GPT-5.6 Terra 输入费率归一化，绝对单位会在本机额度快照校准时抵消。未知模型回退为原始 Token 权重，不保存提示词、工具结果、账户 ID、套餐或积分余额。少量仍使用 legacy rate card 的企业账户不适用该 token-based 权重。

估算器按“本地日期 + 根任务”聚合，而不是只按根任务聚合。连续活动区段仍以 15 分钟为界；1–3 个百分点的快照台阶形成校准桶。校准使用所有任务的稳健中位额度权重/百分点，不再为单个任务复用自己的异常换算率。样本足够时，偏离中位数四倍以上的桶视为并发或延迟污染，不直接归因，其额度权重改用全局换算率补足。已直接覆盖的桶按其中各日任务的额度权重分摊百分点。

所有本机日任务估算之和不得超过账户权威已用百分比。缺少有效快照、窗口过期或模型权重不可校准时只显示原始 Token；界面继续用 `≈`、置信度和“账户总用量含所有设备”说明不确定性。

## 数据迁移与验证

Usage Ledger 升级 schema。旧账本保留逐日 Token，但丢弃与新权重单位不兼容的旧额度观察；仍属于活动额度窗口的线程清除解析检查点并从 rollout 重建额度观察，从而补齐模型权重。已结束窗口不强制全量重扫。

测试覆盖：

- 同一根任务跨两天产生两个独立估算键；
- 原始 Token 较少但输出权重更高的任务获得更高估算；
- 受并发污染的异常百分点台阶不会直接归给本机任务；
- 本机估算总和上限、过期窗口和旧 schema 迁移；
- 点击日期后的 SwiftUI 编译、完整测试、真实账本复算和演示弹窗截图。
