# 榜单详情与趋势交互收尾设计

## Build 32 用户反馈修订

- 展开榜单只显示一次指标表头；每个模型行仅展示对应数值，避免重复“费用”“耗时”等列名。
- 趋势悬浮详情在 1–3 条曲线时使用单列，在 4–5 条曲线时才切换双列，在不遮挡曲线的前提下压缩横向占用。
- 曲线替换菜单明确区分“当前颜色的模型”和“已被其他颜色使用的模型”，两者都不可重复选择，并在菜单文字中说明颜色归属。
- `StatusItemController` 统一负责弹窗关闭生命周期：保留 `NSPopover.transient`，同时按 AppKit 建议监听应用内外鼠标按下事件。SwiftUI 菜单的嵌套事件循环结束后，外部点击监听仍持续有效。

## Build 31 用户反馈修订

- 展开榜单把辅助指标放入模型信息与主排名数值之间，形成横向列式数据区，不再挤在模型名下方。
- 悬浮详情恢复到曲线绘图区上方；预留稳定的顶部空间并仅做水平边界适配，不再把卡片推入曲线。
- 消除趋势区域鼠标跟踪时的亮暗闪动，保持下方曲线控件稳定。

## 结构方案

1. `RankingSection` 在“展开 + 设置开启”时持有唯一表头；`RankRow` 只负责输出与表头对齐的数值。左侧是名次与模型信息，中间是辅助指标列，最右依旧是高对比度的主排名值。智商、费用、耗时榜排除当前主指标；综合榜展示三项原始值。
2. 设置由 `AppSettings` 单一持有并持久化，缺省值为 `false`；看板直接读取该状态，不复制临时开关。
3. 趋势悬浮注释只对水平方向采用 Swift Charts 的图表边界适配，纵向保持在绘图区上方。图表上方预留固定通道；三条以内逐模型单行展示，四到五条才改为双列。
4. 连续悬浮状态下放到独立的趋势绘图子视图，避免每次跨越日期都重算曲线编辑器和整张卡片。趋势卡作为包含多个控件的复合容器，使用静态玻璃表面；真正的按钮和菜单仍保留各自的交互反馈。
5. 模型目录为每个模型提供稳定 `compactLabel`，趋势槽只负责展示；完整名称继续用于帮助文本和辅助功能。
6. 状态栏弹窗的外部点击关闭由 AppKit 控制器统一持有。应用内监听忽略弹窗和状态栏按钮自身，应用外监听只观察鼠标按下；弹窗关闭时立即移除监听，避免常驻事件处理。

- Build 33 已由用户完成最终手动验收，确认表格排版、悬浮位置、筛选菜单关闭生命周期与整体流畅度符合发布要求。
