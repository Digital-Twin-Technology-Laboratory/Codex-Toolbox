# 1.4.2 性能优化实施约定

用户于 2026-10-23 明确授权实施，目标为修复 1.4.1 / Build 63 的卡顿、重复读写和后台资源开销，交付签名公证候选包。源码起点 `8e12091545ce9f6c82711a433cd098695c651340`，首个候选 Build 64。

## 已确认的边界

- 保持界面、文案、用户设置、账户隔离、数值口径和现有刷新时效。
- 应用自有历史迁移为 SQLite 增量持久化；保留原始 JSON，提供一次性回退导出。
- 登录凭据自动刷新问题按用户要求暂不改造；审查记录保留该调查项。
- 不安装或替换当前运行应用，不创建正式 Release、标签或上传更新源；安装与真实交互由用户验收。

## 实施与验证

1. 固定源码与本地数据副本，以相同输入对照历史额度算法及原生额度算法。
2. 增量存储采用 DELETE journal、EXTRA 同步、有界锁等待；读取检查点与数据同事务提交。时区变化、旧 schema、清除、回退再升级均不得丢失历史或复活已清除数据。
3. 历史计算和展示投影离开 MainActor；限定一个运行计算与一个最新待处理请求，校验账户、数据与生命周期代次。刷新、取消和辅助进程必须有界。
4. 对真实调用入口增加回归：算法数值和取消、存储恢复、刷新编排、异常子进程、缓存 304 与异常数值。
5. 全量 Swift/Xcode/Rust/Python 测试、Universal 2 构建、签名、公证和装订后交付候选包。

## 验收目标

- Token、账户归属、精确性和缺失状态相同；百分比数值误差不超过 `1e-6`。
- 约 150 天 / 6.5 万观测 / 3.5 万快照及五倍规模；固定增量的五倍历史写入不超过原规模两倍。
- 受控稳态写入降低至少 90%，应用加辅助进程 CPU 时间降低至少 50%；迁移成本单列。
- 柱状图选日、明细和滚动无原卡顿，相关主线程任务不超过 100 ms。
- 收起、展开静置、交互、电池/接电和睡眠唤醒分开记录；后台场景至少 30 分钟，另有至少两小时持续观察。

编译、独立基准、安装和真实设备验收分别记账。未完成的交互或持续能耗验证必须保持待验收，不作为通过。
