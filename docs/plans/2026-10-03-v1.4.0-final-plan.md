## 已实现范围

1. 1–3 个独立 NSStatusItem；增删、启停、排序、重复内容、至少一个启用项。
2. 四种榜单前两名、今日本机 Token、今日 API 等值成本、账户剩余额度。
3. 共用图标、附加数值、排名样式与模型简称。
4. 同一个看板从点击项目打开；临时显示/展开目标模块，关闭后保留用户布局。
5. 独立菜单栏设置页、原生控件、即时预览；旧榜单选择与外观迁移。
6. 自动识别已核实套餐（Plus、Pro 100/200/500 等），未知套餐明确标注。
7. 实际返回的额度窗口；进度条、圆圈和百分比独立组合。
8. 原重置卡模块扩展为账户额度：套餐、剩余比例、重置时间、重置卡、套餐历史。
9. 最新 schema 3 metrics：原始 IQ、total 计分样本、USD 费用、分钟转秒、费用聚合标记；同口径发布历史作为辅助来源。
10. 打开检查、定期刷新、有效缓存与过期提示，源数据时间与检查时间分别显示。
11. 原生聊天排行、账户 Token 历史、套餐周期和功能分项；本机统计保持独立。

## 数据读取与边界

固定版本 Rust 只读组件随应用打包，官方认证组件处理凭据。Swift 只接收结构化统计与脱敏标识；不接收令牌、Cookie、邮箱或原始账户 ID。目录使用最近 30 天活跃的最多 100 个本机根聊天，归并可枚举子代理，排除异常树，显示查询范围与未提供项。按账户隔离缓存、合并重复请求，每 5 分钟检查原生分析，打开相关界面也检查；切换账户拒收旧结果。

原生聊天比例是聊天累计用量占当前完整套餐额度的比例，可超过 100%。原生 Credits 是实际余额扣款；本机 Credits 与 API 等值成本是各自估算。原生数据不能覆盖本机“今日”统计。账户 Token 逐日日期按官方 UTC 日期显示，未返回的日期不补零。套餐使用官方开始/结束边界、data_as_of、coverage_complete、approximate 与 accounting_complete。

费用标注跟随每行 price_aggregation；不把中位数称作平均值。旧有效榜单仍可在离线时显示，但不会复用旧路由校验器。旧成本快照在 schema 切换时隔离；发布历史只有费用聚合方式一致才进入同一成本曲线。辅助历史失败不覆盖当前榜单。
