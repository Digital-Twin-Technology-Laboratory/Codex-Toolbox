# Codex Toolbox 1.3.1 Network Recovery Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make Radar refreshes and Sparkle update checks recover cleanly from the temporary no-route window around sleep, wake, login, Wi-Fi recovery, and local-proxy startup without hiding real server, payload, signature, extraction, or installation failures.

**Architecture:** Add a Foundation-only transient-network classifier and bounded retry policy to `CodexToolboxCore`. Pause app-owned schedulers during sleep, resume them after a short wake grace period, let Radar use `URLSession.waitsForConnectivity`, and keep Sparkle responsible for its complete security pipeline while `AppUpdateManager` distinguishes user-initiated and scheduled checks at the delegate boundary.

**Tech Stack:** Swift 6, Foundation `URLSession`/`NSError`, AppKit `NSWorkspace` notifications, Swift Observation, SwiftUI, Sparkle 2.9.2, XCTest, SwiftPM, XcodeGen.

**Step 3: Implement the pure policy**

Implement these public values and no UI state:

```swift
public enum TransientNetworkFailure: Sendable, Equatable {
    case offline
    case connectionLost
    case timedOut
    case cannotReachHost
}

public enum NetworkRecoveryPolicy {
    public static func failure(in error: any Error) -> TransientNetworkFailure? {
        var current: NSError? = error as NSError
        var visited = Set<ObjectIdentifier>()

        while let candidate = current {
            let identity = ObjectIdentifier(candidate)
            guard visited.insert(identity).inserted else { break }

            if candidate.domain == NSURLErrorDomain,
               let code = URLError.Code(rawValue: candidate.code) {
                switch code {
                case .notConnectedToInternet:
                    return .offline
                case .networkConnectionLost:
                    return .connectionLost
                case .timedOut:
                    return .timedOut
                case .cannotConnectToHost, .cannotFindHost, .dnsLookupFailed:
                    return .cannotReachHost
                default:
                    break
                }
            }

            current = candidate.userInfo[NSUnderlyingErrorKey] as? NSError
        }
        return nil
    }

    public static func interactiveRetryDelay(after completedRetries: Int) -> Duration? {
        [.seconds(2), .seconds(5)].indices.contains(completedRetries)
            ? [.seconds(2), .seconds(5)][completedRetries]
            : nil
    }

    public static func backgroundRetryDelay(after completedRetries: Int) -> Duration? {
        completedRetries == 0 ? .seconds(30) : nil
    }
}
```

Keep the error-chain traversal bounded by cycle detection. Do not classify HTTP status, payload, cache, Sparkle signature, extraction, or installation errors here.

**Step 3: Implement the pure update decision types**

Implement:

```swift
public enum UpdateCheckOrigin: Sendable, Equatable {
    case userInitiated
    case scheduled
}

public enum UpdateFailureAction: Sendable, Equatable {
    case retry(after: Duration)
    case preservePreviousState
    case present(String)
}

public enum UpdateRecoveryPolicy {
    public static func action(
        origin: UpdateCheckOrigin,
        completedRetries: Int,
        error: any Error
    ) -> UpdateFailureAction {
        guard NetworkRecoveryPolicy.failure(in: error) != nil else {
            return .present("无法完成更新检查，请稍后重试。")
        }

        switch origin {
        case .userInitiated:
            if let delay = NetworkRecoveryPolicy.interactiveRetryDelay(after: completedRetries) {
                return .retry(after: delay)
            }
            return .present("暂时无法连接更新服务器，请检查网络或代理后重试。")
        case .scheduled:
            if let delay = NetworkRecoveryPolicy.backgroundRetryDelay(after: completedRetries) {
                return .retry(after: delay)
            }
            return .preservePreviousState
        }
    }
}
```

**Step 3: Centralize cycle-failure handling**

- If the error is the internal sleep sentinel, restore `preCheckState`, clear the pending intent, and do not display or retry it.
- If `applicationIsAwake` is false, cancel recovery bookkeeping and restore `preCheckState`, even when an already-running request finishes with a normal network error after sleep began.
- On success, cancel the retry task, clear retry counters and pending intent, and set `.upToDate` only if still checking/retrying.

- `.preservePreviousState`: restore `preCheckState` and clear recovery bookkeeping.
- `.present`: set `.failed` with the policy's Chinese message and clear recovery bookkeeping.
